Emergencies do not wait for a package manager

emerag

The emergency agent, in three sizes. From a 58 KB C client that runs on Windows 98/2000/XP, through a 530-630 KB Rust agent, to the full 1.6-2 MB build with certificates and every feature. One static file. No runtime. No dependency hell.

Three sizes. One job.

Nano
58-82 KB

For the machine Rust cannot reach.

  • C89, Visual C++ 6.0
  • Windows 98 / ME / NT4 / 2000 / XP
  • TLS 1.3, one cipher suite
  • Chat Completions only
  • no CA bundle, no verification
  • prompt-based shell protocol
  • /help /compact /clear /yolo /model
Lite
530-630 KB

Almost the whole agent, without the CA bundle.

  • all tools + Lua engine
  • sessions, MCP, skills, subagents
  • OAuth and provider catalog
  • no embedded CAs
  • certificate checks disabled
  • modern Windows/Linux + rust9x
Full
1.6-2.0 MB

The reference build. Certificates and all.

  • same full feature set
  • embedded 118-CA bundle
  • certificate verification on
  • best default for rescue media
  • x86, ARM, RISC-V, s390x
  • zero shared libraries
The tiers are honest: nano is a Chat-only C client with no certificate checking. Lite is the real Rust agent with the CA bundle removed and verification disabled. Full is the same agent with certificates intact. If the network may be hostile, use full.
58 KB is not a full HTTPS stack. Nano speaks TLS 1.3 with one cipher suite, HTTP/1.1, and Chat Completions. It cannot use other APIs, MCP, tools JSON, or certificates. That is the point.

Built for the bad day

Windows 98 to XP?

Nano is built with VC6 and WinSock 2. It does not need a Rust runtime, a TLS DLL, or a modern CPU.

Minimal OpenWrt?

Lite is a static musl binary: 555 KB on ARM64/ARMv7 routers, 630 KB on x86_64. Nano covers x86_64 Linux.

Read-only root?

The installer executes from /dev/shm or another writable tmpfs. Nothing is written to disk.

DNS lying to you?

Lite/full have resolver fallback, --dns and --resolve. Nano has --ip while keeping the hostname for SNI.

Beside a fork bomb?

No daemon, no helper processes, no runtime that can fork. If the kernel can still exec a static binary, emerag can start.

Serial console?

Lite/full have ASCII and cooked modes. Nano is plain line input and prints everything it runs.

One line. No installation.

# 58 KB nano, from RAM
wget -qO- https://xtlsoft.github.io/emerag/install.sh | sh -s -- --run --nano

# 530 KB lite, from RAM
wget -qO- https://xtlsoft.github.io/emerag/install.sh | sh -s -- --run --lite

# full agent
wget -qO- https://xtlsoft.github.io/emerag/install.sh | sh -s -- --run

# install to ~/.local/bin
wget -qO- https://xtlsoft.github.io/emerag/install.sh | sh

The installer uses curl, wget or busybox wget, verifies SHA-256, and falls back from a noexec TMPDIR to /dev/shm. Nano Linux is x86_64-only; Windows binaries are direct downloads.

Nano and lite do not verify certificates. That is a deliberate size/feature trade, not an accident. Full does. A fork bomb that exhausts the kernel PID table can prevent any new process from starting; emerag never forks a daemon or helper of its own. Lite/full 98/2000 builds require the rust9x toolchain and are not ship-ready artifacts; nano is the native path.

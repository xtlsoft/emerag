  • x86, ARM, RISC-V, s390x, Windows

Why the core is separate: it omits the provider adapters and agent framework entirely, not just features. It speaks one protocol path — Chat Completions over HTTP/1.1 + SSE with TLS — and links only the TLS/HTTP/JSON substrate plus a five-tool loop. Responses, Anthropic Messages, OAuth and MCP are not compiled in. The full build keeps everything.

Built for the bad day

Read-only root?

The installer can execute from /dev/shm or another writable tmpfs. Nothing is written to disk.

DNS lying to you?

Built-in resolver fallback, --dns, --resolve, and hostname-preserving TLS.

No package manager?

No Node, Python, OpenSSL, glibc or runtime to install. One file, one process.

Serial console?

ASCII mode, cooked input, 40-column prompts, no alternate screen required.

Beside a fork bomb?

No daemon, no helper processes, no runtime that can fork. If the kernel can still exec a static binary, emerag can start.

Broken shell?

The full build ships a Lua-subset engine for filesystem and process work without a shell.

One line. No installation.

# full agent, executed from RAM
wget -qO- http://10.20.2.226:8899/install.sh | sh -s -- --run --mini

# 300 KB core
wget -qO- http://10.20.2.226:8899/install.sh | sh -s -- --run --lite

# install to ~/.local/bin instead
wget -qO- http://10.20.2.226:8899/install.sh | sh

The installer uses curl, wget or busybox wget, verifies SHA-256, and falls back from a noexec TMPDIR to /dev/shm. Read-only root filesystems are fine.

Windows 2000/XP are not supported by Rust's standard library; use the 32-bit Linux build on that hardware. A fork bomb that exhausts the kernel PID table can prevent any new process from starting; emerag never forks a daemon or helper of its own. “Full” refers to the mini build's feature set; the core intentionally trades features for size.
